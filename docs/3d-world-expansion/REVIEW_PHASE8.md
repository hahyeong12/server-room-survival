# Phase 8 독립 정적 리뷰와 수정

2026-11-26. 사용자가 요구한 독립 코드 리뷰를 별도 에이전트(`phase8_review`)가 수행했다. 하위 세션에는 파일·셸 도구가 제공되지 않아, 주 에이전트가 실제 코드 본문과 변경 내용을 전달했다. **전달한 parser/renderer/session/adapter/UI 본문에 대한 독립 정적 리뷰**이며, 리뷰 에이전트가 파일 전체를 직접 읽거나 테스트를 실행했다고 주장하지 않는다. 실행 검증은 주 에이전트가 별도로 수행한다.

| 지적 | 수정 | 검증 경로 |
| --- | --- | --- |
| P1 해석 응답에 `correct`/`wrong` 정답 키 노출 | 공개 명령/출력에서 제거, 중립 a/b 선택지만 전송, 엔진에서만 채점. 관측별 표시 순서 변화. 후반 오답은 정답 문구를 주지 않음 | Python 키 미노출·정답 순서 회귀, JS 중립 선택지, 브라우저 실제 해석 |
| P2 token 생략으로 오래된 화면 검사 우회 | 외부 command API는 문자열 token 필수. 내부 순수 엔진 호출과 구분 | 어댑터 token 누락/오래된 token 거절 |
| P1 정답 후보에만 `_proof`를 적용하여 응답 차이로 원인 추측 | 제출한 가설 후보의 증거 요건을 모든 후보에 동일 적용 | Python 모든 후보의 동일 근거 부족 반례 |
| P1 cluster 존재가 CrashLoop 원인을 노출 | 장애 전부터 정해진 고객 업무 배포 환경으로 결정. DNS·용량·혼잡 업무도 같은 Kubernetes 환경 사용 | DNS 장애의 정상 Pod/없는 직전 로그·환경 없는 업무 회귀 |
| P2 ping 표본 문구와 journal -n 출력 불일치 | 제한된 표본 표현, 실제 최근 N줄 적용 | N=1/3/10/20 각각 검사 |
| P2 node가 list/dict이면 TypeError | 문자열 자료형을 먼저 검증하고 context 오류 반환 | Python list/dict/None/int 반례 |
| P2 응답 대기 중 다음 입력이 지워짐 | 요청 직후 입력·조립·사건/노드 선택 잠금, 응답 후 다시 활성화 | 지연된 실제 브라우저 요청 검사 |
| P2 사건/노드 변경 후 이전 임시 응답이 새 화면에 적용 | 요청의 사건/노드/게임 세대와 현재 화면 비교, 프롬프트는 요청 당시 노드 사용 | 대기 중 UI 잠금 + 게임 ID/상태 token 회귀 |
| P2 `clear`가 다른 사건의 출력도 숨김 | 사건 ID별 clear 시퀀스로 분리. 엔진 증거는 삭제하지 않음 | 실제 두 사건의 출력 전환/clear 검사 |

추가 자체 점검: ToR 업링크를 worker NIC 장애로 오인하지 않도록 link/ethtool은 네트워크 노드에 한정했고, traceroute 첫 홉은 선택 노드의 route와 일치시켰다. storage IP ping과 고장 랙 IP ping을 구별한다. 정상 GPU 노드 관측을 다른 GPU의 장애 증거로 쓰지 못하게 출력·기록·사전/사후 `_proof` 모두 `eligible` 범위를 적용한다. 새 슬롯 열기 실패는 해당 호출이 만든 파일만 정리한다.

최종 실행 결과와 리뷰 수정 후 재시험 결과는 `QA_REPORT_PHASE8.md` 및 `qa/phase8`의 JSON/로그에 기록한다.


## 인계 후 2차 독립 리뷰 (Claude Code, 2026-11-26)

Codex 사용량 한도로 인계받은 뒤, **파일 도구와 실행 환경을 가진** 별도 리뷰 에이전트가 변경 전체를 직접 읽고 Python 탐침 스크립트(OS 임시 DB)로 재현했습니다(브라우저·포트 미사용, 파일 수정 없음). 12건 중 10건을 실행으로 확인했습니다. 수정 커밋은 `ea15dc0`, 재검증 후 추가 수정은 범위 규칙 커밋입니다.

| 지적 | 확인 | 수정 |
| --- | --- | --- |
| 정상 랙 ping·정상 GPU 노드에서 `eligible:false`와 특수 문구가 ToR·GPU 장치 사건에서만 나와 숨은 원인을 알려 줌 | 실행 | 증거 범위를 모든 원인에 같은 규칙(이 요청의 스토리지·작업 서버)으로 바꾸고, 정상 노드·범위 밖 대상의 출력을 원인과 무관하게 동일하게 함. `eligible`·사건 단위 `status`는 화면으로 보내지 않음 |
| 해석 두 선택지를 차례로 눌러 통과 가능 | 실행 | 관측당 첫 답만 인정, 답한 뒤 버튼 잠금, 해석 요청도 화면 토큰 필수 |
| 복구 뒤 `kubectl logs --previous`가 크래시 로그를 지어냄 | 실행 | 실제로 반복 재시작 중일 때만 직전 컨테이너 존재, 그 외 BadRequest(종료 1) |

**재검증에서 발견된 새 누출(중요):** 1차 수정 후 범위 안의 관측이 엔진에 사건 단위 판독(다른 서버의 Xid, 끊긴 랙의 0/3)을 그대로 기록해, 정상 노드만 본 플레이어도 원인을 확정할 수 있었습니다. 노드·대상 의존 관측은 **영향 범위 전체를 비교했을 때만** 엔진 증거로 기록하도록 바꿨습니다(위 참고 문서의 증거 범위 규칙). 범위를 다 보지 않은 가설·사후 확인은 확인하지 않은 대상을 안내하며, 이 안내는 숨은 원인과 무관합니다.

**남은 한계(수정하지 않음):** 해석은 관측마다 2지선다이며 정답·오답 문장이 명령별로 고정되어 있습니다. 오답 뒤 같은 명령을 다시 실행해 다른 문장을 고르면 통과할 수 있으나, 오해석 횟수는 근무 결과에 남습니다. 관측 출력 전체를 저장하므로 저장 크기는 관측 수에 비례해 커집니다.
