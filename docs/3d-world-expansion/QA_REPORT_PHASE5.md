## 브라우저 QA 방식

- 격리 스택: Python 엔진(포트 8775, OS 임시 저장 폴더, 종료 후 삭제) + 별도 Vite(5175, 별도 캐시). 사용자의 `saves/`, Python 저장, 5173의 다른 Vite는 건드리지 않습니다.
- **상태 변경은 실제 UI 이벤트만**: 3D 캔버스 클릭(랙·건물), 공간 탭, 내 모니터 탭·버튼, 랙 카드 [작업 시작], 시간 버튼, 선배 대화 버튼, 결과 화면 버튼, Lab 구간 버튼·선택 상자·터미널 키보드 입력. API는 전후 상태 읽기(`window.worldQA`)와 파일 해시·SQLite 읽기 전용 비교에만 씁니다.
- 최종 실행은 **seed 없이** 제1장부터 화면으로 플레이합니다. 실패 검사는 그 캠페인 저장의 장 시작 지점에서 메뉴 "장 선택"(새 슬롯)으로 시작합니다. `--seed`(어댑터 행동으로 캠페인을 미리 만드는 개발용 단축)는 실패 검사 반복 개발에만 썼고, 그 결과는 `phase5-qa-partial.json`(Git 제외)에만 기록됩니다.
