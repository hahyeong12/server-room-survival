## 8. 한계와 미구현 (정직한 표기)

- **무시된 사건은 근무를 끝내지 않습니다**(Phase 7부터의 기존 규칙). 정지된 작업은 기한을 넘겨도 완료되지 않고, 근무 시간 제한도 없습니다. 바꾸면 핵심 규칙이 달라지므로 사용자 결정 사항으로 남깁니다.
- **Phase 7 사건/Linux 근무의 동의 판정 내림 식**(`int(x+9)//10*10`)은 기존 판정 의미를 지키려고 유지했습니다. Phase 9 덧층만 `ceil10`을 씁니다.
- **공유 범위 사건의 자유 교대 적격성**: 냉각·UPS·ToR 사건은 주 요청의 기한 여유만 확인합니다. 다른 작업은 계획 중단·이전으로 대응할 수 있습니다.
- **감속형 사건의 완료 시각**: 혼잡·I/O 사건은 남은 작업이 20~40분이면 임시 우회와 근본 조치의 완료 시각이 같을 수 있습니다.
- **브라우저 사건 유형**: 브라우저에서 도달한 자유 사건은 7종이고, 10종 전체는 Python 테스트로 확인했습니다.
- **150% 배율**: Chrome 기기 배율 에뮬레이션입니다. 실제 Windows 배율 설정은 바꾸지 않았습니다.
- **Tk GUI 311개**는 미실행입니다.
- **사람의 플레이 테스트**(재미·난도 체감)는 하지 않았습니다. Phase 10 사용자 평가 대상입니다.
- 모든 사건 수치와 로그는 교육용 가상 모델입니다.
