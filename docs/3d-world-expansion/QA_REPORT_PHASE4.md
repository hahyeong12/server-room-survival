## 브라우저 QA 방식

- `scripts/qa-lib.mjs`가 **격리 스택**을 띄웁니다: Python 엔진(포트 8775, OS 임시 폴더 저장, 종료 후 삭제) + 별도 Vite(포트 5175, 별도 의존성 캐시). 사용자의 `saves/`·Python 저장·실행 중인 다른 Vite는 건드리지 않습니다.
- 상태 변경은 **실제 UI 이벤트만**: 3D 캔버스 클릭/두 번 클릭(투영 좌표), 상단 공간 탭, ← 상위 공간, 내 모니터 탭·버튼, 랙 카드 버튼, 시간 버튼, 선배 대화 버튼. `window.worldQA`는 읽기 전용입니다.
- 화면에 "다음 단계를 대신 실행하는" 버튼은 없습니다(`#primary-action`/`.coach-target`이 존재하지 않음을 검사). 튜토리얼 드라이버는 단계마다 **그 단계의 실제 조작 핸들러**를 실행하고, 그 조작 뒤에 단계가 바뀌었는지 확인합니다. 또 각 단계에서 코치가 실제 DOM 요소나 3D 대상(국가·건물·랙)을 강조하고 있는지 기록합니다.

## 남은 위험·한계

- **사람의 플레이 평가 전:** 자동 QA는 정해진 경로와 대표 오조작만 다룹니다. 처음 보는 사람이 단계 문구만으로 길을 찾는지, 18단계가 길게 느껴지지 않는지는 최종 사용자 평가 대상입니다.
- **실제 Windows 배율 변경 미검증:** 150%는 `deviceScaleFactor` 에뮬레이션입니다. 물리 마우스·다중 모니터도 미검증.
- **교육용 장애는 연출:** 튜토리얼 장애는 어댑터가 기존 교육용 `inject_server_fault`로 거는 시나리오 이벤트입니다(화면에 '교육용 훈련 장애'로 표시). 이후 계산은 모두 엔진입니다.
- **자유 운영 네트워크 장애 UI는 자동 QA 미검증:** 무작위(시드) 장애라 경로를 고정하지 않았습니다. 대응 버튼은 엔진 `respond`를 그대로 호출하며 단위 수준의 장면 표시만 검사했습니다.
- **엔진 미실행 시:** 3D 공간 탐색과 메뉴의 연결 안내만 됩니다(오프라인 플레이 없음).
- **Chrome "Target crashed"(Phase 3.2 기록):** 이번 실행에서는 재현되지 않았고 원인은 여전히 미확정입니다.
- **실행 중이던 다른 Vite(5173, 12:22 시작):** 의존성 캐시가 오래되어 504를 냈습니다. 이 프로세스는 이 작업이 띄운 것이 아니어서 종료하지 않았습니다. 일반 실행 전 해당 터미널에서 종료하거나 `npm run play`를 새로 실행하세요.
- **제2장 이후 3D 미이식:** 제1장 클리어 화면은 이를 명시합니다(Phase 5).
