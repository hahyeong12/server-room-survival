## 2. 설계 결정

### 2.1 v1 보존: 업무는 v1 템플릿, 사건은 별도 버전 콘텐츠

- 고객 업무(자원·기한·허용 모드)는 **기존 `catalog_v1.json` 템플릿을 그대로** 씁니다(`global_v1:` 시나리오, 지문 불변). 사건 교대의 요청도 v1 템플릿의 의미로 접수·검증됩니다.
- 장애 원인·관측·조치·교대 일정은 **별도 버전 관리형 사건 콘텐츠** `aidc/incidents/incidents_v1.json`에 둡니다. 사건은 요청의 시나리오를 바꾸지 않고, 요청 번호에 연결된 별도 상태(`incident` 블록)로 저장됩니다.
- 이것이 `catalog_v2`와 같은 효과를 내는 이유: (1) v1 키의 의미·지문이 바뀌지 않고 `tests/global_catalog_v1_fingerprints.json`이 그대로 통과, (2) 사건 콘텐츠는 자체 `version`과 사건 유형별 지문을 저장 파일에 고정하고 다시 열 때 다르면 거부(소급 재해석 금지), (3) v1 글로벌 저장은 사건 블록이 없으므로 그대로 열리며 자동 마이그레이션하지 않습니다.

### 2.2 세션·저장

- `aidc/incidents/session.py` `IncidentSession(GlobalSession)`: 접수·동의·원장·시간·기한·점수·저장은 기존 경로 그대로. 사건 상태 기계와 교대 A~C·개별 사건 연습만 더합니다.
- 저장: 3D 폴더의 새 파일 `aidc_3d_incident_NNN.db`, `simulation_state.mode='incident'` + `global`(교대 진행) + `incident`(사건 상태). SQL 구조 변경 없음. 기본 `GameSession`·`GlobalSession`은 사건 저장을 열지 않고, `IncidentSession`은 다른 모드 저장을 열지 않습니다.
- 해금: 이 3D 폴더에 **글로벌 교대 3을 클리어한 교대 근무 저장**이 있을 때만 장애 대응 근무 A가 열립니다(읽기 전용 확인). 개별 사건 연습은 언제든(진급 기록 없음). 원래 Phase 4~6 진행·결과는 손대지 않습니다.

## 3. 사건 모델 (교육용 가상 모델)

### 3.1 상태 전이

```text
armed ─(작업 진행률이 정해진 지점 도달, 한 번만)→ alert
alert ─[범위 확인]→ investigating
investigating ─[관측 기록]* → [가설 선택]
    · 그 가설을 판단할 관측이 기록에 없으면: '근거 부족'(정답 여부와 무관하게 같은 문구)
    · 관측과 모순되면: '반박됨' + 관측값으로 이유 기록(오진 횟수 +1)
    · 관측과 일치하면: diagnosed (원인 확정)
diagnosed ─[조치]→ 결과: 해결(복구 n분) / 완화(영향 제거·원인 남음) / 개선 없음(10분 조치 대기) / 허용 안 됨(사유)
    · 팀 승인 필요 조치는 [팀 호출] 후 승인 시각 이후만, 고객 조건 변경은 고객 동의 후만
recovering ─(가상 시간)→ monitoring (원인 해소·영향 해제, 정상 실행 재개)
monitoring ─(정상 실행 10분 경과 + 복구 뒤 재관측)→ [사후 확인] → verified
verified ─[고객 보고]→ closed
어느 단계든: 영향이 남은 채 제한 시간 초과(UPS 배터리·열 보호) 또는 대상 작업 실패 → failed
```

조사 전(진단 확정 전)에는 복구·완화 조치가 모두 거부됩니다. 고객 안내([고객 영향 안내])와 관측은 언제든 허용됩니다. 같은 행동의 이중 클릭은 엔진이 멱등(이미 기록) 또는 거부로 판정합니다.

### 4.4 사실(실무)과 게임 가상 모델의 구분

- **사실로 가져온 것**: 사고 대응의 역할 분리·영향 범위 확인·완화 우선·고객 안내·사후 분석(SRE), DCGM 건강 검사·Xid로 장치 오류 분류, OOM은 장치 고장과 다르다는 점, DNS는 IP 도달성과 별개로 실패할 수 있다는 점, 재시작 반복(CrashLoop)은 이벤트·로그·직전 변경으로 원인을 본다는 점, 디스크 공간 소진 시 `No space left on device`, 흡입 온도 모니터링, UPS 배터리 운전 경보와 설비 조작은 담당 팀의 일이라는 점.
- **게임용 가상 모델**: 모든 수치(RTT·이용률·지연 ms·유량·온도·배터리 %·보호 시간 20분·열 한계 40분·승인 10분·복구 10~30분), 서버동 배치(이중 업링크·냉각 구역·UPS 계통), 장비 ID·로그 문장, 고객 동의 판정식(기한 안이면 동의). 실제 장비의 열/유체/전기 동작이나 특정 제품의 경보 순서를 재현하지 않으며, 화면의 명령어는 예시일 뿐 실행되지 않습니다(입력 가능한 가상 명령은 Phase 8 범위).
- **화면에서 보이는 것의 기준**: 세계지도·캠퍼스·관제 화면은 진단 전 증상만 보여 줍니다(위치 추정 안 함, 해저 구간을 빨갛게 하지 않음). 시설 내부 계기(펌프·UPS·포트 LED)와 서버동 랙의 물리 표시(ToR 포트 DOWN·냉각 구역 경고·UPS 배터리)는 그 건물에 들어갔을 때 보이는 현장 정보로 엔진 상태를 그대로 그립니다. 다만 원인 확정은 관측을 **기록**하고 가설을 판정받아야만 됩니다.
