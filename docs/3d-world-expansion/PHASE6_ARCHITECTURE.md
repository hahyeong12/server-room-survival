### 1.3 결정

- 새 고객 요청은 화면 데이터가 아니라 **기존 엔진 경로**로 처리합니다: `missions` 행(고객·업무) → `_receive`(조건·기한 고정, 요청 메시지) → `allocation_options`/`choose_plan`(동의·원장·서버 조각 검증) → `advance_time`(진행·기한·만료) → `_finish_if_needed`(반환·점수·고객 반응) → `_persist`(저장).
- 카탈로그의 업무 템플릿은 **버전이 붙은 새 scenario 키**(`global_v1:<templateId>`)로 `game.SCENARIOS`에 등록합니다. 기존 키는 재할당하지 않으며, 같은 버전 키의 내용은 테스트가 해시로 고정합니다(바꾸려면 새 버전 키).
- 글로벌 근무는 별도 저장(`aidc_3d_global_NNN.db`, 3D 저장 폴더)과 별도 모드(`global`)입니다. 정규 스토리 1~5장·튜토리얼·자유 운영·Lab의 수치와 순서는 바꾸지 않습니다.
- 새 장애 원인·Linux 명령은 Phase 7/8 범위입니다. 글로벌 근무의 장애 확률은 0이며(자원·동의·기한·경합이 이번 판단 대상), 이 사실을 화면과 문서에 적습니다.

### 2.4 저장·호환

- 글로벌 근무는 3D 저장 폴더의 `aidc_3d_global_NNN.db`입니다. `simulation_state`에 `mode='global'`과 `global` 블록(종류·교대·도착 기록·결과·이력)을 더하며 SQL 구조는 바꾸지 않습니다.
- 요청마다 `conditions.catalog`(버전·템플릿·지문·고객·도시·좌표·업무)를 저장합니다. 다시 열 때 현재 카탈로그의 지문과 다르면 오류로 거부합니다(소급 재해석 금지). v1 규칙 필드의 지문은 `tests/global_catalog_v1_fingerprints.json`으로 고정했습니다.
- 기본 `GameSession`은 글로벌 저장을 열지 않고("모드별 저장 파일"), `GlobalSession`은 자유 운영·스토리 저장을 열지 않습니다.
- 옛 `SG/JP/US` 코드는 카탈로그의 legacy 별칭으로 남아 제1~5장·이전 저장의 요청 ID·경로·마커가 그대로입니다.

## 4. Phase 7 인계

- **장애 연결 지점**: 글로벌 세션은 `incident_chance=0`입니다. 카탈로그 템플릿에 기존 `incident`/`hardware_fault` 같은 시나리오 키를 넣으면 기존 엔진 경로(`_start`, `advance_time`, `_trigger_story_faults`)가 그대로 동작하지만, 글로벌 화면의 진단 탭·결과표는 아직 장애 행을 다루지 않습니다. 새 장애 원인(DNS·포트·과열·UPS 등)은 엔진에 원인 모델을 먼저 추가하고, 지도는 `world.paths[].link`·`segments`를 그대로 쓰면 됩니다(진단 전 "원인 미확인" 유지).
- **새 콘텐츠**: 같은 키의 규칙을 바꾸지 말고 `catalog_v2.json`·`global_v2:` 키를 추가합니다. `tests/global_catalog_v1_fingerprints.json`이 v1 불변을 지킵니다. 사이트 추가는 JSON만 고치면 Python·지도·어댑터가 함께 반영됩니다(좌표는 테스트의 국가 범위·육지 검사 통과 필요).
- **교대 추가**: `shifts`에 도착 일정(첫 도착 0분)·목표·코칭 수준을 넣으면 됩니다. 결과 판정은 `GlobalSession.shift_result()`(엔진 기록 집계) 하나입니다.
- **남은 개선**: 기존 튜토리얼/스토리 모드의 1366×768 150% 배치, 교대 브리핑 전 배정 허용 여부 결정, 같은 도시 2건의 브라우저 시연(자유 운영에서 발생 가능).
