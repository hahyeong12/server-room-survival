## 실행 방법

기존 네이티브 하네스는 `main()`을 거치지 않고 Tk 루트를 직접 만듭니다. 그래서 실험 플래그 대신 같은 함수(`aidc.ui.dpi.enable_system_awareness()`)를 Tk 생성 전에 부르는 래퍼 [run_aware.py](run_aware.py)로 기존 QA 스크립트를 **수정 없이** 실행했습니다.

```powershell
$env:PYTHONIOENCODING = 'utf-8'   # 출력 리디렉션 시 cp949 오류 방지(아래 참고)
python docs/qa/dpi-acceptance-001/run_aware.py tests/qa/autoplay_chapter5.py --self-check
python docs/qa/dpi-acceptance-001/run_aware.py tests/qa/check_treeview_input.py <새 폴더>
python docs/qa/dpi-acceptance-001/run_aware.py tests/qa/autoplay_chapter5.py --focus <새 폴더 A>
python docs/qa/dpi-acceptance-001/run_aware.py tests/qa/autoplay_chapter5.py <새 폴더 B> <폴더 A>/result.json
python docs/qa/dpi-acceptance-001/run_aware.py docs/qa/dpi-acceptance-001/check_racks.py <새 폴더>
```

- **환경:** Windows 11, 125% 배율(AppliedDPI 120), 단일 모니터. 인식 모드의 물리 1920×1080 = Tk 화면 크기이고, 캡처 배율은 1.000입니다(비인식은 1.250). `C:\anaconda3\python.exe` 3.14.6, Tk 8.6.15. 인식 모드 `tk scaling` 1.668.
- **저장:** 모든 플레이는 하네스의 임시 폴더(`%TEMP%\srs_qa_*`) 슬롯만 사용했습니다.
- **출력 인코딩:** 출력을 파일로 넘기면 Windows 기본 인코딩(cp949)이 `—` 문자를 쓰지 못해 첫 Treeview 검사가 로그 출력에서 중단됐습니다. 게임·DPI와 무관한 실행 환경 문제이며, `PYTHONIOENCODING=utf-8`로 새 폴더에서 다시 실행했습니다.

## 5. 발견 사항

### F-1. 인식 모드에서 배정창 세로 중앙 오차가 QA 허용치(±8px)를 넘음 — 재현됨, 기능 영향 없음, 미수정

**현상:** 제1장 고객 3명의 배정 설정창 중앙 오차가 (0, −11)px입니다. 비인식에서는 같은 위치가 (0, −6)px입니다.

**재현:**
- 정규 플레이 3/3
- [dpi-review-001 캡처](../dpi-review-001/capture-summary.json)의 (0, −11)
- 단독 측정(관제실 최대화 + 1000×740 설계 창): 비인식 −6, 인식 −12

**원인(측정):**
- 배정창은 작업 영역 높이에 가깝습니다. `centered_bounds`는 창 아래쪽에 "제목 표시줄 + 아래 테두리" 전체 높이를 비워 두는 보수적인 아래쪽 제한을 써서, 창을 위쪽 여백까지 밀어 올립니다.
- 실제로는 두 모드 모두 정중앙에 놓아도 작업 영역 안에 들어갑니다(인식: 아래 끝 996 ≤ 1005).
- 이 계산은 비인식에서도 같지만, 인식 모드에서 창이 커져 오차가 허용치를 넘었습니다.
- 창틀·여백 보정을 빼도 −9px라, 보정 값의 문제가 아닙니다.

**영향:**
- 창은 작업 영역 안에 있습니다.
- 모든 버튼의 접근성·잘림 검사는 PASS이고, 배정·진행 결과는 비인식과 같습니다.
- 눈에 보이는 차이는 925px 높이 창이 위로 약 11px 치우치는 정도입니다.

**미수정 이유:**
- 고치려면 공용 순수 함수 `centered_bounds`의 아래쪽 제한 계산을 바꿔야 합니다.
- 그러면 **기본(비인식) 모드의 배치도 바뀌고**(−6 → 0 예상), 기존 순수 함수 테스트(`test_tutorial_ux` 등)의 기대값도 바뀝니다.
- 지시에 따라 수정 범위가 커지는 경우로 보고 우선 보고합니다.

## 6. 남은 문제와 미검증 범위

- **결정 필요:** F-1 수정 여부. `centered_bounds` 계산 변경 시 기본 모드 배치와 순수 함수 테스트 기대값이 바뀝니다.

- **미검증:** 다른 배율(100%·150%), 다중 모니터, 실행 중 배율 변경. 이번 검증은 125% 단일 모니터 한 대입니다.
