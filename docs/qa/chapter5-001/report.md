# chapter5-001 — 제5장 실제 GUI 자동 플레이 QA

이번 작업은 기존 제5장 기능의 QA입니다. 새 네트워크 사건·명령·숙련도/등급·게임 규칙·난이도·점수·저장 형식·전역 DPI를 변경하지 않았습니다. 기존 QA 보고서도 수정하지 않았습니다.

정규 제1→5장 실제 GUI 플레이를 **1회 완료**했습니다. **321 PASS / FAIL 0 / 실행 오류 없음**, 제5장 Stage1~5를 모두 통과했고 연수 고객 작업도 기한 내 정상 완료·전량 반환했습니다. 별도 연습 입력 fixture는76 PASS, 관련 Tk11 PASS, 비GUI 전체759 PASS입니다. 사용자 저장·잠금24개의 목록과 SHA-256은 모두 동일합니다. [정규 결과](result.json), [요약](summary.json), [사용자 데이터 비교](user-data-comparison.json).

## 실행 조건과 구분

각 Stage의 학습 묶음 전후, 그리고 터미널 명령마다 게임 시각·전체 자원·서버 원장·장비 상태·모든 작업 상태/점수·요청 조건·동의 제안을 비교했습니다. 학습 기록만 추가되며 운영 상태는 같았습니다. 게임 상태 변경은 관제실의 실제 배정·시간 진행·우회 대응에서만 발생했습니다.

Stage4/5에서 입력한 실제 명령은 아래와 같습니다. 교육용 주소이며 호스트 OS의 셸이나 실제 네트워크에서 실행한 명령이 아닙니다.

```text
ping -z 192.168.10.1
ping -c 3 192.168.10.1
ping -c 3 10.0.0.20
ip route
```

장애 중 가까운 라우터는3/3, 원격은0/3입니다. 경로 출력은 `10.0.0.0/24 via 192.168.10.1 dev eth0 proto static`입니다. 우회 후 같은 원격 ping은3/3입니다. 구조도·관제실·터미널은 같은 요청·가상 시각·원장·경로 상태를 사용했습니다. 주 경로의 물리 상태를 고치는 대신 백업으로 전환하는 모델이라 우회 후에도 주 경로 자체는 DOWN인 점과 통신 가능 상태를 구분합니다.

Stage5 통과 순간에는 네트워크 관측은 복구됐지만 고객 작업은 `recovering`일 수 있습니다. 이를 고객 작업 완료로 세지 않고 실제 시간 버튼으로 준비·남은 작업을 끝낸 뒤 정상 완료·기한 준수·전량 반환을 추가 확인합니다.

| 사고 요구의 상승 | Stage1은 구조와 영향 연결, Stage2는 도구의 질문 범위, Stage3은 구문과 수치 읽기, Stage4는 직접 증거 수집과 사실/추정 구분, Stage5는 관찰→판단→조치→재검증의 순서를 요구함 | 모두 같은 사건이며 질문/판정이 고정됨. 한 경로를 재현하는 능력이 새로운 장애로 전이되는지는 미검증 |
| 힌트의 변화 | Stage2·3에는 명령 의미·목적·확인 불가 정보와 해석 도움이 있음. Stage4는 선택지/블록 대신 help와 입력 안내. Stage5는 구조도의 장애 표시와 해석 도움을 숨김 | Stage5에도 단계별 체크리스트·원인 선택지·관제실 대응 버튼은 남고, 앞 Stage에서 경로 단절을 이미 경험함. 완전한 무힌트 진단이 아님 |
| 증거 기반 통과 | 탭 열기·도구 선택·명령 실행·복구 클릭 각각만으로 통과하지 않는 실제 경로를 확인함. 조치 전 증거와 후속 응답의 순서를 요구함 | 준비된 선택지와 자동 정오 판정에 대한 기능 검사이며, 학생이 판단 근거를 스스로 서술하는 평가는 아님 |
| 현재 상태의 연결 | 장애 중 근거리3/3·원격0/3, 우회 후 원격3/3이 구조도·관제실 상태와 일치함. GPU/전력 점유는 장애 중 유지되고 작업 종료 후 반환됨 | IP·라우터·지연·손실·패킷 애니메이션은 교육용 모형. 실제 패킷 캡처나 Linux 커널/장비 측정이 아님 |
| 오류의 학습성 | `ping -z`는 옵션 오류와 지원 범위 안내, 대상 누락 블록은 용법 오류, 목적이 다른 도구는 다른 질문에 답한다는 피드백을 제공함. 시간/자원/점수 벌점 없음 | 모든 오답/미지원 명령/보안 입력을 네이티브로 열거한 것은 아님. 기존 단위 회귀와 구분 |
| Stage5의 독립성 | 필요한 명령을 직접 입력하고, 이전 Stage 기록을 대신 쓰지 않으며 사후 관측이 필요함 | **이미 경험한 `ch3_path` 사건의 시연**임. 새로운 장애의 독립 해결, 숙련도 인증·등급·완성형 셸은 검증되지 않았고 이번 범위 밖임 |

실제 Linux와의 의미 비교도 표시된 교육 범위 안에서 판단했습니다. `ping`의 ICMP ECHO 요청과 `-c` 송신 횟수라는 기본 의미는 [iputils 자체 매뉴얼](https://github.com/iputils/iputils/blob/master/doc/ping.xml)과 맞습니다. 게임은 일부 옵션·주소·관측만 지원하며 실제 OS에서 실행하지 않는다고 터미널에 명시합니다.

`ip route`의 경로 표시는 설정된 경로에 관한 정보입니다. 라우팅 테이블에 경로가 있다는 사실만으로 원격 응답이나 물리 회선 정상을 증명하지는 않습니다. [ip-route(8) 매뉴얼](https://man7.org/linux/man-pages/man8/ip-route.8.html)의 경로 조회 의미와 구분해 읽어야 합니다. 이번 Stage4는 물리 회선 단절·서버 장비 고장을 확정 불가로 분류하게 하므로 이 구분을 가르칩니다. Stage5의 같은 관측으로 고르는 경로 단절은 **이 제한된 재사용 사건에서의 가장 타당한 가설**이며 일반 네트워크에서의 단독 확증으로 보고하지 않습니다.

## 남은 UX·교육 과제와 미검증

- **낮은 우선순위, Lab 헤더 잘림:** 긴 고객/업무 설명이 한 줄에 들어가지 않습니다. 집중 모드 캡처에서 `Engineering Lab 연습 · 정규 기록 아님 | 요청 #1 · Merlion AI / 싱가포르 · 생성형 AI 모델 학습 요청`의 중간/끝이 잘립니다. 목표 카드·과제·실행·관제실 복귀 버튼은 실제 입력으로 접근했으며 입력 흐름을 막지는 않았습니다. 줄바꿈/요약/상세 표시 등은 별도 수정 협의 대상입니다.
- **완료 의미의 구분:** Stage5 사후 ping 직후 학습5/5 결과가 먼저 열리고 고객 작업은 복구 준비/실행 중일 수 있습니다. 현재 구현의 학습 완료와 고객 완료를 구분해 보고했습니다. 결과 화면에서 둘의 차이를 더 분명히 안내할지는 후속 UX 검토 대상입니다.
- **독립성·설명 평가:** 같은 사건/선택지 기반 시연임을 계속 표시해야 합니다. 향후 학습자가 증거와 가설의 한계를 설명하는 방식은 별도 설계 대상이며 이번에 새 평가·등급을 만들지 않았습니다.
- **흰 프레임·DPI:** 기존 미해결 상태를 유지합니다. 기존 모니터 기록을 남겼지만 원인·빈도·해결을 확정하는 실험이나 전역 DPI/렌더링 수정은 하지 않았습니다. 다른 실제 배율/모니터, 최소 Lab 창 크기와 모든 해상도 조합은 이번 네이티브 플레이 범위 밖입니다.
- 모든 오답 조합, 다른 서버/배정안/모드, 사건 재접수, 디스크 이어하기, 저장 실패 주입, 모든 클립보드/히스토리 입력, 새 장애/명령/제5장 이후 콘텐츠는 이번 실제 플레이에서 검증하지 않았습니다. 기존 관련 단위·Tk 회귀의 검증을 실제 마우스/키보드 실적으로 바꾸어 세지 않습니다.
