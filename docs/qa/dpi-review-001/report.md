# dpi-review-001 — Windows 고배율 화면 흐림: 실험용 System DPI 인식(B-1)

Windows 125% 배율에서 게임 글자가 흐린 문제를 다뤘습니다. 실험 플래그를 켰을 때만 **System DPI Aware**를 적용하고, 화면 배율만큼 UI를 보정했습니다(B-1). **기본 실행은 지금과 같은 DPI 비인식이며, 기본값으로 전환하지 않았습니다.**

게임 규칙·시간·자원·점수·고객 동의·저장 형식, 제5장 시나리오와 Engineering Lab 기능은 바꾸지 않았습니다. Per-Monitor DPI 인식과 B-0(배율 보정 없이 인식만 켜기)은 범위 밖입니다.

## 1. 흐림의 원인(측정)

- 게임 프로세스는 DPI 비인식(`GetProcessDpiAwareness = 0`)입니다. `python.exe`에 DPI 매니페스트가 없고 게임 코드에도 설정이 없었습니다.
- Tk는 96DPI로 선명하게 그리지만, **Windows 창 합성기가 완성된 비트맵을 1.25배로 늘릴 때** 흐려집니다. 400×300 창이 실제로는 500×375 픽셀입니다. 1px 검은 선이 `26,178,128,77,229` 같은 회색으로 번집니다.
- `DPI_AWARENESS_CONTEXT_UNAWARE_GDISCALED`(GDI 스케일링)는 Tk에서 효과가 없었습니다(60.2%, 비인식과 같음).
- Tk 8.6.15 DLL에는 모니터별 DPI API가 없습니다. 그래서 Per-Monitor 인식은 다른 배율 모니터에서 크기를 맞추지 못할 것으로 보고 제외했습니다(미검증 추정).

## 3. 글꼴은 정확히 1.25배가 되지 않습니다(측정)

Tk는 pt 글꼴을 정수 px로 반올림하므로, 크기마다 커지는 비율이 다릅니다.

| 글꼴 | 줄 높이(비인식 → 인식) | 비율 |
| --- | --- | --- |
| Malgun Gothic 8pt | 13 → 17px | 1.31 |
| 9pt | 15 → 20px | 1.33 |
| 10pt | 17 → 23px | 1.35 |
| 11pt | 20 → 25px | 1.25 |
| 20pt | 37 → 45px | 1.22 |

- `tk scaling`을 하나의 값으로 바꿔도, px 단위 글꼴을 써도, 일부 크기는 1.25배를 넘었습니다(측정 범위 최대 1.30~1.46).
- 그래서 글꼴을 억지로 맞추지 않았습니다. 대신 글자가 들어갈 공간을 정하는 고정값(줄바꿈 폭, 목록 행 높이, 격자 최소 크기 등)을 배율에 맞췄습니다.
- 배율 자체를 1.33 등으로 키우는 방법은 `GetDpiForSystem()/96` 규칙과 "기존과 같은 물리 크기" 목표에 어긋나 채택하지 않았습니다.
- 결과적으로 **인식 모드의 글자는 기존보다 약 4% 크게 보입니다**([확대 비교](shots/zoom_control_room_text.png)).

## 8. 남은 문제와 미검증 범위

- **기본값 전환은 하지 않았습니다.** 기본 ON 여부는 사용자 결정 사항입니다.
- **검증 범위:** 125% 노트북 한 대(단일 모니터)에서만 검증했습니다. 다음은 미검증입니다.
  - 실제 100%·150%·175% 배율(배율 1.5·1.75·2.0의 계산은 단위 테스트로만 확인)
  - 다중 모니터·배율이 다른 모니터로 창 이동
  - 실행 중 배율 변경
  - 다른 PC의 글꼴
- **다른 배율 모니터:** System Aware는 로그인 시점 배율 기준입니다. 다른 배율 모니터에서는 Windows가 다시 비트맵 확대를 할 것으로 예상합니다(그 모니터에서만 흐림, 크기는 유지, 미검증).
- **여백(padx/pady):** 보정하지 않았습니다. 인식 모드에서는 여백이 약 20% 좁아 보이고, 랙 표시 방식이 달라질 수 있습니다(5절).
- **글꼴 비례 한계:** 글꼴은 정확히 비례하지 않습니다(3절). 최소 창 크기에서 여유가 적은 화면은, 새 UI를 추가할 때 두 모드로 검증해야 합니다.
- **QA 도구:** 기존 QA 도구(`tests/qa/flash_bench.py` 등)는 비인식 모드 전제이며 이번에 바꾸지 않았습니다. 관측 프로세스와 게임 프로세스가 분리된 도구로 인식 모드를 측정하려면 두 프로세스의 인식 상태를 맞춰야 합니다.
- **교육창 외 다른 창의 첫 표시 흰 프레임:** 이번 범위 밖입니다.
