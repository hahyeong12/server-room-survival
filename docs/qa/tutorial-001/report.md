# QA tutorial-001 — 튜토리얼 실제 자동 플레이

> 대상: 서버실 생존기 v0.9-4b, 커밋 `fcf3da5`, 노트북 실행. 게임 코드는 수정하지 않았습니다.
> 이 문서는 실제 Tk 화면을 OS 마우스 입력으로 조작한 첫 자동 플레이 기록입니다. **확인한 항목만 통과로 적었고, 확인하지 못한 항목은 '미검증'으로 표시했습니다.**

## 요약

- **튜토리얼 완주: 성공.** 공식 실행(run5)에서 시작 화면 → 튜토리얼 → 교육 4쪽 → 요청 확인 → 배정 설정 → 작업 시작 → +10분 → **MISSION SUCCESS(100.0점, 기한 내 완료, GPU 7·전력 7 반환)** → 메인 메뉴까지 실제 클릭 15회로 진행했습니다. 자동 검사 46개 중 41개 통과, 5개 실패입니다.
- 게임 규칙을 우회하거나 성공을 직접 호출하지 않았습니다. 엔진 상태는 검증용 **조회만** 했습니다.
- 사용자 저장 데이터(루트 DB 12개)는 실행 전후 MD5가 같습니다. 플레이는 임시 디렉터리의 별도 슬롯에서만 진행했습니다.
- 주요 문제(자세히는 [발견한 문제](#발견한-문제)):
  - **Q-01 (높음)** 기본 창 크기에서는 STEP 2의 금색 강조 대상 [요청 확인]이 다른 패널 아래에 가려져 눌리지 않습니다. 창을 최대화해야 진행할 수 있었습니다.
  - **Q-02 (높음, 5회 중 3회)** 고객 요청서 창이 관제실 중심보다 110px 아래에 놓여, [확인 · 운영실로]를 포함한 하단 버튼이 작업 표시줄 뒤로 숨습니다. 원인은 `frame_offset()`이 숨긴 창의 기본 위치를 창틀 두께로 오인하는 것이며, 진단 기록으로 확인했습니다.
  - **Q-03 (중간~높음, 2회 중 2회)** 요청서 [확인 · 운영실로]의 첫 클릭은 본문 타이핑만 완성하고 창을 닫지 않습니다. 창이 남아 있는 동안은 이후 단계의 금색 강조가 모두 사라집니다.
  - **Q-04 (중간)** STEP 3에서 목표 카드는 [배정 설정·선택]을 가리키는데, 금색 강조는 Inspector의 [배정 미리보기] 탭에 있습니다.

## 자동화 방식 — 실제 GUI 입력과 내부 조회의 구분

| 구분 | 방법 | 쓰인 곳 |
| --- | --- | --- |
| **실제 GUI 입력** | Win32 `SetCursorPos` + `SendInput`(왼쪽 버튼 누름/뗌). OS 입력 큐를 거쳐 Tk 이벤트 루프가 처리합니다. | 모든 버튼·카드·배정안 선택, 제목 표시줄 [최대화]·[X] |
| **실제 화면 캡처** | `PIL.ImageGrab`으로 화면을 캡처했습니다(그림을 재구성하지 않음). 배율 1.25를 보정해 게임 창 영역을 잘랐습니다. | 모든 스크린샷, 흰 창 점등 검사 |
| 위젯 위치 조회 | Tk `winfo_rootx/rooty/width/height`로 클릭 좌표를 계산하고, `winfo_containing`으로 그 점에 실제로 보이는 위젯을 확인합니다. | 클릭 좌표, 가려짐 판정 |
| 상태 조회(읽기 전용) | `session.story.onboarding.step`, 서버 원장, 가용 GPU/전력, 진행률, `dialog.placement`, `tutorial_highlight` 값을 읽기만 했습니다. | 기대 결과 비교 |
| 진단 래퍼 | `window_placement.frame_offset`을 감싸 입력·출력만 기록했습니다(원래 함수를 그대로 호출하며 결과도 바꾸지 않음). | Q-02 원인 확인 |
| 종료 정리 | 마지막에 게임의 기존 종료 처리(`on_close`/`root.destroy`)를 호출하고, 하네스가 만든 임시 디렉터리만 삭제했습니다. | 테스트 정리 |

안전 장치: 클릭 직전에 그 좌표의 최상위 창이 게임 프로세스의 창인지(`WindowFromPoint` → PID) 확인합니다. 다른 프로그램이나 작업 표시줄이면 클릭하지 않고 중단합니다(run1에서 실제로 작동).

코드: [tests/qa/gui_driver.py](../../../tests/qa/gui_driver.py)(하네스), [tests/qa/autoplay_tutorial.py](../../../tests/qa/autoplay_tutorial.py)(시나리오). 일반 테스트 탐색(`unittest discover`, `tests.run_headless`)에는 포함되지 않습니다.

## 저장 데이터 보호

- 실행 전후 저장소 루트의 `aidc_game.db`와 `aidc_story_slot_001~011.db`(12개) MD5가 모두 같습니다(5회 실행 모두).
- 하네스는 게임 모듈을 import하기 전에 `DB_PATH`·`STORY_DB_PATH`를 임시 디렉터리로 바꾸고 `ModeSelection(story_slots=StorySlots(임시 디렉터리))`로 실행했습니다. 튜토리얼 슬롯은 `aidc_story_slot_001.db`(임시 디렉터리)로 만들어졌습니다. 튜토리얼 모드는 체크포인트를 만들지 않습니다(`capture()`는 `mode == 'story'`일 때만 동작).
- 실행 뒤 임시 디렉터리(`aidc_story_slot_001.db`, `.lock`)만 삭제했습니다. 실행 전 게임 프로세스는 없었습니다.

## 발견한 문제

### Q-01 기본 창에서 STEP 2 강조 버튼 [요청 확인]이 가려져 누를 수 없음 — 높음

- **발생 단계:** STEP 2 요청 확인(교육창을 닫은 직후)
- **현상:** 관제실 기본 창 1280×680(논리)에서 가운데 영역(요청함·서버 랙·Inspector)이 필요한 높이 492px 중 82px만 받습니다. 그 안의 [요청 확인] 버튼은 아래 요청 상세 패널(`.!frame4`)에 덮입니다. 금색 테두리(형제 Frame)는 그려지지만 관계없는 글자 "배정 권장 D1 10:00 · 완료 기한…" 위에 뜹니다. 테두리 안을 클릭하면 상세 패널 라벨이 클릭을 받아 아무 일도 일어나지 않습니다(단계 `request` 유지).
- **재현:** 1536×864(125% 배율 1920×1080) 화면에서 튜토리얼 시작 → 교육창 4쪽 → [첫 업무 시작] → 강조 테두리 안을 클릭. 공식 실행을 포함해 6회 모두 재현됐습니다.
- **캡처:** [04_step2_request_button_hidden.png](screenshots/04_step2_request_button_hidden.png)
- **측정값:** 루트 grid 각 행의 요구 높이는 213 + 78 + **492** + 185 + 48 + 48 = 1064px이고, 창은 680px입니다. 가중치가 있는 2행(가운데 영역)만 줄어듭니다.
- **최대화 후에도 남는 문제:** 1536×793에서도 필요한 높이가 부족합니다. '운영 작업 · 진행률' 목록 제목과 접수 안내 라벨이 상세 패널에 가려집니다(위젯 가려짐 2건). 즉 이 해상도에서는 진행 중 작업 목록이 보이지 않습니다.
- **가능한 원인:** 창 높이가 `min(680, 화면높이-100)`으로 고정되고, 레이아웃의 최소 높이가 이보다 큽니다. 강조 표시는 대상의 실제 가시성을 확인하지 않습니다.
- **개선 제안(구현하지 않음):** 화면 크기에 맞춰 시작 시 최대화하거나 높이를 보장하기, 가운데 영역 축약 또는 스크롤, 강조 전에 `winfo_containing`으로 대상이 보이는지 확인하고 보이지 않으면 대체 대상([AIDC LINK · 새 업무 메시지])을 안내하기.

### Q-02 고객 요청서 창이 110px 아래에 놓여 하단 버튼이 작업 표시줄 뒤로 숨음 — 높음(간헐, 정식 5회 중 3회)

- **발생 단계:** STEP 2, [요청 확인]으로 AIDC LINK 고객 요청서를 열 때(관제실 최대화 상태)
- **현상:** 요청서(880×660)의 중심이 관제실 중심보다 110px 아래에 놓입니다. [◀ 이전]·[확인 · 운영실로]·[전체 보기]·[건너뛰기]가 모두 작업 영역(아래 끝 y=816) 밖에 있습니다. 사용자는 제목 표시줄의 [X]나 창 끌기로만 닫을 수 있습니다. 나머지 2회는 6px 차이로 정상 범위였습니다.
- **재현:** 위 Q-01 이후 관제실 최대화 → [요청 확인]. 결과는 Windows가 그 순간 새 창에 정한 기본 위치에 따라 달라집니다.
- **캡처:** [05_request_dialog_pushed_down.png](screenshots/05_request_dialog_pushed_down.png). 작업 표시줄을 제외하고 사용자에게 보이는 영역까지만 잘랐으며, 버튼 줄이 화면 아래에서 잘려 있습니다.
- **원인(진단 기록으로 확인):** `aidc/ui/window_placement.py`의 `frame_offset()`은 숨긴(withdraw) 창에서 `winfo_rootx/rooty − winfo_x/y`를 창틀 두께로 씁니다. 부모 값을 쓰는 대체 경로는 이 값이 (0,0)일 때만 탑니다. 실제 숨긴 창은 `winfo_x/y = (0,0)`이고 `winfo_rootx/rooty`에는 Windows 기본(계단식) 위치가 들어 있었습니다.

  | 실행 | 숨긴 요청서의 root 좌표 → `frame_offset` 결과 | 목표 y | 결과 |
  | --- | --- | --- | --- |
  | run5 | (164, 187) → (164, 187) | 12 + 187 = **199** | 110px 아래 |
  | run4 | (60, 83) → (60, 83) | 12 + 83 = 95 | 6px 아래 |

  세로 660px 창은 `y − dy`가 화면 경계 제한(`max(area_top + 12, …)`)에 걸리고, 이어서 `target = y + dy`로 잘못된 dy가 그대로 목표에 더해집니다. 표시 후 보정 단계는 이 잘못된 목표와 실제 위치를 비교하므로 차이가 없다고 기록합니다(`dialog.placement` = target (328,199) / actual (328,199) / offset (0,110)). 교육창처럼 경계 제한에 걸리지 않는 창은 보정 단계가 바로잡아 정상으로 보입니다. 정상 창틀 오프셋은 관제실 기준 (8, 31)입니다.
- **개선 제안(구현하지 않음):** 숨긴 창이면 항상 부모의 창틀 오프셋을 쓰거나, 경계 제한을 적용한 뒤 목표를 다시 계산하기. 표시 후 작업 영역 이탈 검사를 추가하기.

### Q-03 요청서 [확인 · 운영실로] 첫 클릭이 창을 닫지 않고, 그동안 금색 강조가 모두 사라짐 — 중간~높음

- **발생 단계:** STEP 2 → 3, 요청서가 화면 안에 정상 배치된 경우(run2, run4)
- **현상:** 창이 뜬 지 약 2초 뒤 [확인 · 운영실로]를 누르면 본문 타이핑만 완성되고 창은 그대로입니다. 버튼 이름은 처음부터 "확인 · 운영실로"로 보입니다. 관제실은 `message_window`가 열려 있으면 교육 강조를 지우므로, 사용자가 다시 누르기 전까지 STEP 3 배정안·STEP 4 작업 시작·STEP 5 시간 버튼 강조가 모두 사라집니다. run4에서는 요청서가 열린 채로 튜토리얼이 끝났고, 강조 key는 계속 `None`이었습니다.
- **재현:** 2/2(run2, run4). 탐색 실행처럼 오래 기다린 뒤 누르면 한 번에 닫힙니다.
- **캡처:** [06_request_dialog_not_closed_run4.png](screenshots/06_request_dialog_not_closed_run4.png)(클릭 뒤에도 요청서가 남아 있고 뒤 관제실 STEP 3에 금색 강조가 없음)
- **원인:** `ui.py`의 `MessageDialog.next()`는 `self.shown < len(self.full_text)`이면 `reveal()`만 합니다(타이핑 18ms마다 3글자).

## UX 관찰

### 자동 측정으로 확인한 사실

- 교육창 본문은 4쪽, 쪽당 1~6줄, 한 줄 최대 33자입니다. 데이터의 줄바꿈이 그대로 표시됩니다.
- 교육창 마지막 쪽 버튼은 [◀ 이전]·[첫 업무 시작]·[전체 보기]·[업무로 돌아가기]·[마지막 안내] 5개입니다. 그중 [첫 업무 시작]·[업무로 돌아가기]는 모두 창을 닫고 업무로 돌아가는 동작이고, [마지막 안내]는 이미 마지막 쪽에서도 보입니다.
- 고객 요청서는 요약 카드(GPU·전력·운영 모드·기한·동의)와 아래 원문 메시지가 같은 조건을 두 번 보여 줍니다.
- 상단 HUD("GPU 7/10 · 전력 7/10")와 큰 GPU AVAILABLE·POWER 패널이 같은 수치를 동시에 표시합니다.
- 작업 시작 직후 AIDC LINK에 "새 업무 메시지 1건"이 생깁니다(내용은 열지 않음).
- 결과창 버튼은 2개이고 좌우 여백이 대칭입니다. 주요 버튼 [메인 메뉴]가 더 큽니다.

### AI의 주관적 평가(캡처를 보고 판단, 사람의 확인 필요)

- **첫 화면:** 큰 로고·아이콘이 있는 모드 카드 3장과 단일 주요 버튼으로 게임 타이틀처럼 느껴집니다. '자유·연습' 카드의 소개 문구만 왼쪽 들여쓰기가 달라 보입니다([01](screenshots/01_title_screen.png)).
- **안내 흐름:** STEP n/5 카드, ✔/●/○ 단계 표시, 선배 한마디, 단계마다 금색 강조 1개의 구조는 다음 행동을 분명히 보여 줍니다. 다만 이 노트북 해상도에서는 Q-01·Q-04 때문에 STEP 2~3에서 흐름이 끊깁니다.
- **글의 양:** 교육창은 짧고 적절합니다. 관제실 요청 상세 문구("새 요청입니다. 조건과 기한을 확인한 뒤 … 나중에 배정할 수 있습니다.")와 요청서 원문은 튜토리얼에 비해 깁니다.
- **시선 흐름:** 교육창 말풍선은 2줄 정도인데 상자가 커서 아래쪽 빈 공간이 넓습니다. 배정창은 ① 운영 모드 → ② 배정안 → 미리보기 → 하단 시작 요약 순서가 자연스럽지만, 금색이 여러 곳에 있어 '지금 누를 것'이 덜 두드러집니다(Q-05).
- **결과창:** MISSION SUCCESS → 수치 타일 → 상세 → 선배 한마디 → 다음 단계 → 버튼 순서로, 시선 흐름이 깔끔합니다.

## 미검증·한계

- **흰 창 점등:** 창 감시는 15ms 간격이고 연속 캡처는 약 90ms 간격(27프레임/2.4초)입니다. 이보다 짧은 점등은 놓칠 수 있습니다. 이번 관측에서 검출되지 않았다는 뜻이며 해결을 뜻하지 않습니다. 이번 흐름에서 시간 진행 직후 새로 뜬 창은 결과창 하나뿐이었습니다(FEEDBACK 창은 나타나지 않음).
- **진행률 중간값:** 처리 10분 작업이라 +10분 한 번으로 0→100%가 됩니다. +30/+60분 버튼은 강조만 확인하고 누르지 않았습니다.
- **해상도:** 이 노트북(1536×864 논리, 125%) 한 가지 조건만 확인했습니다. 데스크톱 1920×1080(100%)은 미검증입니다.
- **다른 경로:** [AIDC LINK · 새 업무 메시지] 상단 버튼, [튜토리얼 건너뛰기], [다시 학습], 교육창 [전체 보기]·[마지막 안내], 절약형 모드는 누르지 않았습니다(미검증).
- **Q-03의 키보드·다른 지연 시간:** 약 2초 뒤 클릭만 확인했습니다. 타이핑 종료 시간은 측정하지 않았습니다.
- **기존 GUI 테스트 스위트**(약 280개)는 실행하지 않았습니다.
