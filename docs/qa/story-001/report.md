# QA story-001 — 제1장 「첫 근무」 실제 자동 플레이

> **부분 실행 후 안전 중단. 제1장 완주·클리어를 확인하지 못했습니다.** 싱가포르는 정상 완료했고, 일본은 작업 시작 직후 중단했습니다. 미국은 접수하지 못했습니다. 사용자는 중단 결과를 보고·Push하도록 선택했습니다. 게임 기능·UI 수정과 추가 GUI 실행은 하지 않았습니다.

## 시작 루틴과 범위

1. 저장소·origin·브랜치를 확인했습니다. 최초 작업 트리는 깨끗했고 `main`이었습니다.
2. 샌드박스의 `.git/FETCH_HEAD` 쓰기 제한으로 첫 Fetch가 거부됐습니다. 권한 확장 후 `git fetch origin`은 성공했습니다. 로컬 HEAD와 `origin/main`은 모두 `8a2ba96`, 앞섬/뒤처짐은 `0/0`이어서 Pull은 하지 않았습니다.
3. `AGENTS.md` → `PROJECT_VISION.md` → 결정 기록 → 학습 설계 → 로드맵 → README/CHANGELOG 및 현재 코드, 모드 재구성 기록을 확인했습니다. 이어 [tutorial-001](../tutorial-001/report.md), [tutorial-002](../tutorial-002/report.md)와 기존 QA 하네스를 분석했습니다.
4. 일부 과거 문서에는 제1장을 단일 고객으로 설명합니다. 현재 `OnboardingProgress(kind='shift')`와 `intro_sg_v1` / `intro_jp_v1` / `intro_us_v1`이 구현 현황의 기준입니다. 기존 문서는 고치지 않았습니다.
5. 변경 범위는 [autoplay_story_ch1.py](../../../tests/qa/autoplay_story_ch1.py)와 이 QA 디렉터리뿐입니다. `gui_driver.py`, `autoplay_tutorial.py`, 게임 코드, tutorial-001/002 기록은 그대로 유지했습니다.

## 실행 방법과 안전 중단

```text
# Windows, 저장소 루트, 실제 데스크톱 캡처·입력 권한이 있는 Python
# 실행 중 마우스·키보드를 사용하지 마세요. 출력 디렉터리는 새 이름을 사용합니다.
python tests/qa/autoplay_story_ch1.py <새 출력 디렉터리>

# 창을 만들지 않는 확인
python tests/qa/autoplay_story_ch1.py --self-check
python -m tests.run_headless
python -m py_compile tests/qa/autoplay_story_ch1.py tests/qa/gui_driver.py tests/qa/autoplay_tutorial.py
```

현재 노트북의 `python` 명령은 실제 Python 대신 Windows 앱 별칭을 가리켜 실행하지 못했습니다. 설치된 Anaconda Python을 명시하여 실행했으며 새 의존성은 설치하지 않았습니다.

기존 `Harness`의 실제 ModeSelection→SimulatorApp 실행, Win32 입력, Tk 좌표/상태 조회, 임시 DB 경로 격리, 실제 화면 캡처, 창 감시를 재사용했습니다. 튜토리얼의 배치·레이아웃 조회 함수도 재사용했습니다. 게임 상태를 바꾸는 세션 메서드나 버튼 `invoke()`로 진행하지 않았습니다. 종료 정리만 기존 `on_close()`를 호출했습니다.

새 시나리오에서만 클릭 직전 좌표를 다시 읽고, 가려짐·화면 밖·다른 최상위 창이면 클릭하지 않습니다. 캡처는 게임 루트의 클라이언트와 작업 영역 안으로 제한하며, 그 위 외부 창이 겹치면 이미지 저장 및 이후 입력을 중단합니다. 기존 하네스의 15ms 창 감시와 시간 진행 후 연속 캡처를 그대로 사용합니다.

| 실행 | 진행 | 종료 이유 | 클릭 | 판정 |
| --- | --- | --- | --- | --- |
| 1 | 모드 선택 화면의 캡처 초기화 | 샌드박스에서 `OSError: screen grab failed` | 0 | 자동화 실행 환경 오류. 게임 결함 아님 |
| 2 | 안내→싱가포르 완료→일본 요청·배정·시작 | 캡처 보호 장치가 외부 창 가림을 감지해 `AbortQA`로 중단 | 21 | QA 미완주. 일본 시간 진행 버튼에는 클릭하지 않음 |

실행 2는 데스크톱 접근 권한을 확보해 실행했습니다. 외부 창 감지 뒤에는 재시도하지 않고 정상 종료했습니다. 당시 보호 장치는 외부 창의 제목·PID를 저장하지 않아 어떤 창이었는지, 일시적 감지였는지는 확정할 수 없습니다. 마지막 실제 캡처는 일본 배정창입니다. 중단 장면은 외부 화면 보호 때문에 저장되지 않았습니다.

재실행 정책에 따라 사용자에게 중단 보고와 마지막 1회 재실행 중 선택을 요청했고, 사용자는 **“현재 중단 결과로 보고·Push”**를 선택했습니다. 전체 GUI 실행은 2회이며, 이후 GUI 테스트나 제2장 플레이를 실행하지 않았습니다.

### UI 확인 범위

- 안내·요청·배정창의 중심 차이는 각각 (0,0), (0,1), (0,-6) 논리 px였습니다. 검사한 중요 버튼은 작업 영역 안에 있었고 클릭됐습니다. 요청서 확인은 SG·JP 모두 한 번에 닫혔습니다.
- 목표 카드는 업무 1/3→2/3 및 요청→배정 검토→시간 진행으로 바뀌었습니다. **스토리 첫 근무는 의도적으로 금색 조작 강조를 사용하지 않습니다.** 코드상 `guided_intro`는 tutorial 모드에만 적용됩니다. 이번 스토리의 강조 없음은 튜토리얼 강조 회귀로 판정하지 않았습니다.
- 실제 [SG 진행 캡처](screenshots/06_1_running.png)에서 서버 랙 제목·GPU 모듈·가용 GPU·전력 막대의 겹침은 보이지 않았습니다. SG 점유 색과 자원 가용 수치는 일치했습니다. Canvas 내부 글자 전부를 자동 측정한 것은 아닙니다.

## AI의 UX·게임 디자인 관찰 의견

이 절은 기능 통과와 별개의 **AI 관찰 의견**입니다. SG 1건과 JP 시작까지의 실제 화면·행동에 근거하며, 사람 대상 재미·학습 효과 실험이나 제1장 전체 평가를 대신하지 않습니다.

| 관점 | 관찰 의견 |

| 고객 전환 연출 | 상태상 전환은 정확했지만, 완료→반환→다음 요청이 한 번에 바뀌어 SG를 잘 마쳤다는 여운이 약했습니다. JP 첫 접수 때 요청함의 새 행까지 한눈에 보이지 않아 배경 숫자만 바뀐 것으로 놓칠 여지가 있습니다 |

## 개선 제안 — 구현하지 않음

1. **P1 — 남은 검증 확보:** 다음에 사용자가 QA를 요청하면 외부 창을 비운 상태에서 JP 완료·미국·최종 결과·다음 장 버튼 표시까지 확인할 필요가 있습니다. 이번 결과로 제1장을 출시 수준의 통과로 판정하면 안 됩니다.
2. **P2 — 현재 고객의 가시성:** 새 요청·선택 고객을 목록에서도 확실히 볼 수 있게 하는 방안을 검토하세요. 요청함·진행 목록의 확보 높이와 현재 선택 행 노출이 후보입니다. 구체적 UI 수정은 별도 합의 대상입니다.
3. **P2 — 반복 속 학습 차이:** 각 고객을 처리하며 무엇을 새로 판단했는지 짧게 돌아볼 수 있으면 좋겠습니다. 동시 작업을 앞당기는 큰 설계 변경 없이도, 고객별 자원 비율·기한을 읽는 이유를 전달할 여지가 있습니다. 제2장의 역할을 침범하는 기능 추가는 이번 제안에 포함하지 않습니다.
4. **P3 — 전환·소개 표시:** 고객 교체와 자원 반환을 짧게 인지할 수 있는 피드백, 스토리 메뉴 소개 문장 잘림을 검토하세요. 매 고객마다 확인 팝업을 늘리면 클릭 피로가 커질 수 있습니다.
5. **QA 보완:** 다음 실행에서는 스크롤 영역의 후보와 실제 버튼 가려짐을 구분해 해석하고, 외부 창 감지 당시 개인정보 없는 위치 진단을 남길 필요가 있습니다. 최종 시나리오에는 가림 감지 시각·캡처 영역 기록과 메뉴 레이아웃 조회를 추가했으나 **GUI로 재검증하지 않았습니다**.

## 저장 데이터 보호

- 실행 1·2 각각의 전후 SHA-256과 파일 집합이 일치했습니다. 기존 **DB 12개 + 잠금 파일 12개 = 24개**입니다. 슬롯·체크포인트·SQLite 보조 파일도 검색 범위에 포함하며, 발견하지 못한 사용자 외부 디렉터리 저장까지 검증했다고 주장하지 않습니다.
- 사용자 DB를 SQLite로 열지 않았습니다. 루트 저장의 파일 해시만 읽었습니다. 실플레이에는 하네스가 만든 시스템 임시 디렉터리와 `StorySlots(임시 디렉터리)`만 사용했습니다.
- 실행 2의 임시 슬롯, 제1장 시작 체크포인트, 슬롯 잠금 파일은 정상 종료 뒤 정리했습니다. 게임 프로세스나 다른 프로그램을 강제 종료하지 않았습니다.
- 원본 DB·슬롯·체크포인트·잠금·개인 경로·임시 출력은 커밋하지 않았습니다. 공개 JSON의 로그에서는 저장소 경로를 `<repo>`로 치환했습니다.
- 기존 QA/게임 파일의 Git 차이는 없으며, `tutorial-002` GUI는 재실행하지 않았습니다. 비GUI 746개 통과가 실제 튜토리얼 GUI 회귀 재확인을 의미하지는 않습니다.
